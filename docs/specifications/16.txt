MODULE TÀI KHOẢN & NGƯỜI DÙNG - NỀN TẢNG MOBILE APP 'ĐẶC SẢN SỐ BẮC GIANG'
I. PHẠM VI MODULE & NGUYÊN TẮC ĐẶC TẢ TỐI ƯU MOBILE APP
Module Tài khoản & Người dùng đóng vai trò hạt nhân quản lý định danh, xác thực, phân quyền và lưu trữ thông tin nền tảng cho toàn bộ hệ thống Đặc sản số Bắc Giang trên Mobile App. Nền tảng được tối ưu triệt để cho các thao tác cảm ứng, xác thực sinh trắc học, định vị GPS native và hệ thống thông báo đẩy (Push Notifications).
1. Sự liên kết nghiệp vụ với các Module theo BRD
Chính sách đơn hàng: Cung cấp thông tin tài khoản Người mua (Khách hàng) và Sổ địa chỉ nhận hàng dữ liệu cho Đơn hàng. Cung cấp thông tin HTX (Người bán) để xác nhận, chuẩn bị đơn.
Hợp tác xã (HTX): Liên kết Tài khoản HTX với Hồ sơ HTX, Mã số thuế (MST duy nhất), quản lý danh mục sản phẩm, cấu hình Preorder và giao hàng hỏa tốc nội tỉnh Bắc Giang.
Cơ quan quản lý nhà nước (Giám sát): Tài khoản Giám sát có quyền truy cập đặc thù (Chỉ xem báo cáo, không chỉnh sửa dữ liệu hệ thống).
Luồng mua hàng & Preorder: Lưu giỏ hàng theo tài khoản, cho phép xem/tìm kiếm sản phẩm công khai khi chưa đăng nhập và bắt buộc xác thực khi đưa vào giỏ/thanh toán.

VII. DANH SÁCH API MOBILE KEY ENDPOINTS
Các API chính phục vụ trao đổi dữ liệu Mobile App & Backend Services:
POST /api/v1/auth/register: Đăng ký tài khoản Khách hàng / Nộp hồ sơ HTX (tải ảnh Giấy phép/Chứng nhận)
POST /api/v1/auth/login: Đăng nhập mật khẩu/OTP, cấp cặp JWT Access & Refresh Token.
POST /api/v1/auth/biometric-login: [MOBILE] Xác thực Đăng nhập bằng Vân tay / Face ID trên thiết bị đã được tin tưởng.
POST /api/v1/auth/device-token: [MOBILE] Cập nhật FCM Token để nhận Push Notification.
GET/POST/PUT /api/v1/me/addresses: Quản lý Sổ địa chỉ GPS Khách hàng.
POST /api/v1/me/addresses: Thêm địa chỉ mới, tiếp nhận tọa độ Latitude & Longitude lấy từ GPS máy để hỗ trợ định vị và tính phí Giao hỏa tốc.
PUT /api/v1/me/addresses/{addressId}: Cập nhật thông tin địa chỉ.
DELETE /api/v1/me/addresses/{addressId}: Xóa địa chỉ khỏi sổ địa chỉ.
GET /api/v1/admin/users: Lấy danh sách, tìm kiếm, lọc tài khoản theo Role/Trạng thái.
POST /api/v1/admin/htx/{htxId}/approve: Admin Phê duyệt hồ sơ HTX, tự động kích hoạt tài khoản ACTIVE và gửi SMS/Push kích hoạt.  
POST /api/v1/admin/htx/{htxId}/reject: Admin Từ chối hồ sơ HTX (kèm lý do).
POST /api/v1/admin/users/{userId}/lock: Admin Khóa tài khoản (bắt buộc nhập lí do) + Gửi Silent Push ngắt Session.
POST /api/v1/admin/users/{userId}/unlock: Admin Mở khóa tài khoản về lại trạng thái ACTIVE

Function ID / Name:
UC-ACC-01 - Đăng ký tài khoản Khách hàng / Nộp Hồ sơ HTX
Mục tiêu:
Cho phép người dùng tự tạo tài khoản Khách hàng hoặc gửi hồ sơ đăng ký HTX để Admin kiểm duyệt ngay trên App.
Actor / Trigger:
Actor: Khách hàng (Khách vãng lai), Đại diện HTX.
Trigger: Người dùng chọn 'Đăng ký' trên App Mobile.
Preconditions:
Chưa đăng nhập hệ thống.
Main Flow (Mobile):
1. Khách chọn 'Đăng ký tài khoản Khách hàng'.
2. App hiển thị Form: Họ tên, Số điện thoại, Email (optional), Mật khẩu.
3. Khách tích 'Đồng ý Điều khoản & Chính sách' -> Nhấn 'Đăng ký'.
4. Hệ thống gửi OTP 6 chữ số qua SMS/ZNS. App tự động bắt SMS Auto-fill OTP.
5. Khách xác nhận OTP -> Kích hoạt `ACTIVE`, tự động đăng nhập và quay lại trang trước đó.
Alt / Exception Flow:
Alternative Flow (Đăng ký HTX): Đại diện HTX nhập MST (kiểm tra duy nhất BR-HTX-02), Tên HTX, SĐT, Địa chỉ, dùng Camera App chụp Giấy phép kinh doanh & Chứng nhận. Hồ sơ ở trạng thái `PENDING_APPROVAL` chờ Admin duyệt.
Exception Flow: SĐT/MST đã tồn tại -> Báo lỗi cụ thể. OTP sai/hết hạn -> Cho gửi lại tối đa 3 lần/15 phút.
Business Rules liên quan:
BR-ACC-001 (SĐT duy nhất đối với Khách hàng); BR-HTX-02 (MST duy nhất đối với HTX); BR-ACC-002 (OTP hiệu lực 120s); BR-ACC-003 (Mật khẩu 8-32 ký tự, đủ ký tự đặc biệt).
Function ID / Name:
UC-ACC-02 - Đăng nhập & Xác thực Biometric
Mục tiêu:
Xác thực danh tính người dùng qua Password, SĐT+OTP hoặc Face ID/Vân tay trên Mobile App.
Actor / Trigger:
Actor: Customer, HTX, Admin, Giám sát.
Trigger: Mở App Mobile và chọn Đăng nhập.
Preconditions:
Tài khoản đã tồn tại trên hệ thống.
Main Flow (Mobile):
1. Đăng nhập lần đầu: Nhập Username/SĐT + Mật khẩu (hoặc SĐT + OTP). Hệ thống trả về JWT Access Token & Refresh Token. App hỏi 'Bật đăng nhập bằng Face ID / Vân tay cho lần sau?'.
2. Đăng nhập lần sau: Nhấn Icon Biometric -> Xác thực vân tay/Face ID native -> Đăng nhập thành công tức thì.
3. Điều hướng theo Role: Customer về Trang chủ; HTX về Dashboard HTX; Giám sát về Báo cáo Mobile.
Alt / Exception Flow:
Exception Flow: Sai mật khẩu -> Báo lỗi chung; Sai quá 5 lần -> Khóa tạm 15 phút. Tài khoản bị `LOCKED` -> Hiển thị Lý do khóa và Hotline hỗ trợ.
Business Rules liên quan:
BR-ACC-004 (Không tiết lộ chi tiết lỗi đăng nhập); BR-ACC-005 (Khóa tạm 15m khi sai 5 lần); Chịu tác động của BR-ACC-016 (Kick session ngay khi Admin khóa).
Function ID / Name:
UC-ACC-03 - Đăng xuất
Mục tiêu:
Hủy phiên làm việc an toàn, xóa Keychain/Keystore và Device Token khỏi hệ thống.
Actor / Trigger:
Actor: Tất cả các Role đã đăng nhập.
Trigger: Chọn 'Đăng xuất' trong Menu Tài khoản trên App.
Preconditions:
Đang ở trạng thái Đã đăng nhập.
Main Flow (Mobile):
1. Khách bấm 'Đăng xuất'.
2. Pop-up Native xác nhận: 'Bạn có chắc chắn muốn đăng xuất?'.
3. Bấm 'Xác nhận' -> Hệ thống thu hồi Refresh Token (Blacklist Redis), hủy `device_token` nhận Push Notification trên Server và xóa Token trong bộ nhớ mã hóa của thiết bị (Keychain/Keystore).
4. Điều hướng về Màn hình Đăng nhập / Trang chủ Khách hàng.
Alt / Exception Flow:
Exception Flow: Token hết hạn từ trước -> Tự động dọn dẹp Cache Client và chuyển về Màn hình Đăng nhập.
Business Rules liên quan:
BR-ACC-015 (Cập nhật danh sách Device Tokens khi đăng xuất).
Function ID / Name:
UC-ACC-04 - Xem & Cập nhật Profile
Mục tiêu:
Quản lý thông tin cá nhân Khách hàng và Hồ sơ pháp lý HTX ngay trên Mobile App.
Actor / Trigger:
Actor: Customer, HTX, Admin, Giám sát.
Trigger: Vào mục 'Hồ sơ cá nhân' trên App.
Preconditions:
Đã đăng nhập.
Main Flow (Mobile):
1. Khách xem Profile -> Cập nhật Họ tên, Email, Avatar (Chụp từ Camera hoặc chọn từ Thư viện ảnh).
2. Đổi mật khẩu: Nhập Pass cũ -> Pass mới -> Xác nhận -> Thoát ra và đăng nhập lại bằng Pass mới.
3. Với HTX: Được xem thông tin pháp lý (MST, Tên HTX). Muốn chỉnh sửa thông tin pháp lý đã duyệt phải gửi yêu cầu 'Duyệt lại hồ sơ'.
Alt / Exception Flow:
Exception Flow: Email trùng lặp -> Báo lỗi Validation. SĐT chính không được sửa trực tiếp.
Business Rules liên quan:
BR-ACC-006 (SĐT không tự sửa trực tiếp); BR-ACC-007 (MST HTX duy nhất và cố định sau khi duyệt).
Function ID / Name:
UC-ACC-05 - Sổ địa chỉ nhận hàng GPS
Mục tiêu:
Quản lý địa chỉ giao hàng của Khách hàng, tích hợp GPS định vị tọa độ phục vụ tính phí Giao hỏa tốc.
Actor / Trigger:
Actor: Khách hàng (CUSTOMER).
Trigger: Vào 'Sổ địa chỉ' hoặc chọn địa chỉ tại bước Checkout Đơn hàng.
Preconditions:
Đã đăng nhập.
Main Flow (Mobile):
1. Thêm địa chỉ mới: Khách bấm '+ Thêm địa chỉ' -> Bấm nút 'Lấy vị trí hiện tại (GPS)' -> App tự động điền Tỉnh/Thành, Quận/Huyện, Phường/Xã và Tọa độ Lat/Long.
2. Khách chỉnh sửa Số nhà/Tên đường, Họ tên người nhận, SĐT người nhận.
3. Tích 'Đặt làm địa chỉ mặc định' -> Bấm 'Lưu'.
4. Liên kết đơn hàng: Khi chốt đơn, hệ thống chụp SNAPSHOT toàn bộ địa chỉ vào bảng Đơn hàng.
Alt / Exception Flow:
Alternative Flow: Khách tự chọn Tỉnh/Thành, Quận/Huyện thủ công từ Picker Menu.
Exception Flow: Đơn Giao hỏa tốc yêu cầu địa chỉ thuộc Bắc Giang, nếu chọn địa chỉ ngoài tỉnh -> Hệ thống thông báo không hỗ trợ hỏa tốc.
Business Rules liên quan:
BR-ACC-008 (Snapshot địa chỉ vào đơn hàng); BR-ACC-009 (Sửa sổ địa chỉ không làm đổi đơn hàng cũ); BR-ACC-010 (Tối đa 10 địa chỉ); BR-ACC-011 (Hỏa tốc bắt buộc nội tỉnh Bắc Giang).
Function ID / Name:
UC-ACC-06 - Admin Cấp tài khoản & Duyệt HTX
Mục tiêu:
Cho phép Admin tạo tài khoản Nội bộ/Giám sát và Phê duyệt kích hoạt tài khoản HTX từ hồ sơ.
Actor / Trigger:
Actor: Admin (SUPER_ADMIN).
Trigger: Vào Màn hình Phê duyệt HTX hoặc Cấp tài khoản trên Admin Portal/App Admin.
Preconditions:
Admin đã đăng nhập.
Main Flow (Mobile):
1. Duyệt HTX: Admin mở danh sách Hồ sơ HTX PENDING_APPROVAL -> Kiểm tra thông tin, giấy phép kinh doanh, chứng nhận  -> Bấm 'Phê duyệt'  -> Trạng thái HTX chuyển ACTIVE.
2. Hệ thống KHÔNG gửi mật khẩu trực tiếp qua SMS/Push. Hệ thống tự động gửi Email/SMS chứa "Link/Mã OTP kích hoạt thiết lập mật khẩu" (hiệu lực 24h) tới SĐT/Email đăng ký của HTX.
3. Đại diện HTX nhấn vào Link/nhập OTP trên App Mobile -> Tự đặt mật khẩu mới cho tài khoản của mình.

Alt / Exception Flow:
Exception Flow: Admin Từ chối duyệt HTX -> Bắt buộc nhập Lý do từ chối  -> Hồ sơ chuyển `REJECTED` để HTX sửa lại.
Business Rules liên quan:
BR-ACC-013 (Admin không cấp quyền cao hơn chính mình); BR-HTX-05 (HTX chỉ được bán hàng sau khi Admin duyệt).
Function ID / Name:
UC-ACC-07 - Admin Khóa / Mở khóa tài khoản
Mục tiêu:
Vô hiệu hóa hoặc khôi phục quyền truy cập của tài khoản, gửi Silent Push kích văng phiên làm việc tức thì.
Actor / Trigger:
Actor: Admin (SUPER_ADMIN).
Trigger: Chọn tài khoản trong Danh sách -> Bấm 'Khóa' hoặc 'Mở khóa'.
Preconditions:
Tài khoản tồn tại trên hệ thống.
Main Flow (Mobile):
1. Admin chọn 'Khóa tài khoản' -> Pop-up bắt buộc nhập 'Lý do khóa'.
2. Bấm 'Xác nhận' -> Hệ thống chuyển `status = LOCKED`, ghi log `locked_by`, `lock_reason`.
3. Đồng thời gửi lềnh Silent Push Notification tới thiết bị Mobile của User -> App Mobile nhận lệnh lập tức xóa local cache/token và chuyển về Màn hình Đăng nhập kèm thông báo lý do bị khóa.
4. Mở khóa: Admin chọn 'Mở khóa' -> Trạng thái về `ACTIVE` -> User đăng nhập lại bình thường.
Alt / Exception Flow:
Exception Flow: Admin cố tình tự khóa chính mình -> Báo lỗi 'Không thể tự khóa tài khoản cá nhân'.
Business Rules liên quan:
BR-ACC-012 (Token bị vô hiệu hóa ngay khi khóa); BR-ACC-013 (Bắt buộc lý do khóa); BR-ACC-016 (Silent Push kick session mobile).
